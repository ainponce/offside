# Offside Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Construir Offside, la plataforma de órdenes de bloqueo en vivo que corre el circuito completo del Desafío Fútbol contra el simulador oficial, con todo el material para presentarla.

**Architecture:** Un solo proceso Node: un motor que sondea el simulador y aplica reglas deterministas, una API HTTP y una interfaz web servida por el mismo proceso. El estado vive en SQLite. Las reglas de decisión son funciones puras; todo lo que toca el simulador pasa por una interfaz `Simulador` que las pruebas reemplazan.

**Tech Stack:** Node ≥ 22.13 (desarrollo en 24), TypeScript ejecutado con `tsx`, `node:sqlite`, Hono, React + Vite + Tailwind, `node:test`. Python 3.9 sin dependencias para las herramientas. pnpm.

**Spec:** `docs/superpowers/specs/2026-11-11-offside-design.md`

**Ejecución elegida:** nativa (una sesión implementa las tareas en orden), con un subagente para la interfaz web (tarea 8) y una revisión independiente al final (tarea 12). Ain pidió avanzar sin pausas, así que no hay ronda de aprobación del plan.

## Global Constraints

- Ninguna orden sale sin la aprobación de un juez con sesión iniciada y de turno según el simulador en el momento del envío.
- Toda orden lleva `vence_min` igual al `fin_min` del partido. No se envían órdenes con el partido terminado.
- Bloqueo por IP solo con las cuatro condiciones de la sección 7.4 del diseño; en cualquier otro caso, por dominio.
- Sin servicios externos en tiempo de ejecución. La URL del simulador es configuración (`SIMULADOR_URL`, por defecto `http://localhost:8080`).
- El código de la organización no se copia al repositorio; se clona en `.simulador/` (ignorado por git).
- Sin claves reales. Solo las claves de demostración del simulador y usuarios de demostración.
- Tiempo de negocio en minutos de partido según el simulador, nunca según el reloj local.
- Interfaz y documentos en español. Licencia MIT.
- `orden_id = OFS-<n expediente, 6 dígitos>-<n medida, 4 dígitos>-<proveedor>-<intento>-<huella[0:16]>`; `expediente_id = EXP-2026-<6 dígitos>`.

## Review Focus

1. El simulador no responde o tarda: el motor sigue vivo, la interfaz muestra "sin conexión", y al volver no duplica órdenes. (Prueba en tarea 4.)
2. Doble toque en "Firmar y ordenar": la segunda aprobación responde 409 y no se envía nada dos veces. (Tarea 4.)
3. Detección incompleta (sin marca, sin captura, base64 inválido, IP sin DNS pasivo): se archiva o se recomienda dominio; nunca rompe el ciclo. (Tareas 2 y 4.)
4. Aprobación en el borde del turno: si al enviar el juez ya no está de turno, no sale la orden y se crea una ratificación. (Tarea 4.)
5. Error ambiguo del proveedor (corte de red, 5xx, 409 por duplicado): se reintenta con el mismo `orden_id` y un 409 se toma como "ya recibida". (Tarea 4.)

### Task 4: Motor, decisiones y despacho

**Files:** Create `src/server/config.ts`, `src/server/simulador.ts`, `src/server/motor.ts`, `src/server/decisiones.ts`, `src/server/despacho.ts`; Test `pruebas/motor.test.ts` (con un `Simulador` falso en memoria definido en `pruebas/simulador-falso.ts`)

**Interfaces — Produces:**

```ts
interface Simulador {
  estado(): Promise<EstadoSim>
  partido(): Promise<Partido>
  detecciones(desde: number): Promise<{ minuto_actual: number; detecciones: Deteccion[] }>
  dnsIp(ip: string): Promise<DnsIp | null>
  dnsDominio(dominio: string): Promise<DnsDominio | null>
  proveedores(): Promise<Proveedor[]>
  enviarOrden(proveedorId: string, orden: OrdenSim): Promise<{ ok: true } | { ok: false; estado: number; error: string }>
  ordenes(proveedorId: string): Promise<EstadoOrdenSim[]>
  levantar(proveedorId: string, ordenId: string, cuerpo: { juez_id: string; firma: string; motivo: string }): Promise<{ ok: true } | { ok: false; estado: number; error: string }>
  reclamos(desde: number): Promise<{ minuto_actual: number; reclamos: ReclamoSim[] }>
}
class Motor { constructor(ctx: Contexto); tick(): Promise<void>; iniciar(intervaloMs: number): void; detener(): void }
aprobarMedida(ctx, medidaId: string, juezId: string): Promise<{ ok: true } | { ok: false; codigo: 403 | 404 | 409; error: string }>
rechazarMedida(ctx, medidaId: string, juezId: string, motivo: string): Promise<...>
reconsiderarMedida(ctx, medidaId: string, juezId: string): Promise<...>
```

`Contexto = { db, sim, auditoria, config, jueces, alCambiar(): void }`.

- [ ] **Step 1: pruebas que fallan** (cada una avanza el simulador falso y llama `motor.tick()`):
  - Detección pirata nueva crea expediente, servidor y medida `inicial` pendiente con instantánea y huella.
  - Segunda detección del mismo servidor no crea otra medida.
  - Misma marca en otro servidor, con la primera aprobada, crea medida `ampliacion`.
  - Detección de licenciatario y de otra señal se archivan sin medida.
  - Aprobar envía una orden por proveedor con `vence_min === fin_min`, firma válida y `orden_id` que termina en `huella[0:16]`.
  - Aprobar con un juez fuera de turno devuelve 403 y no envía nada.
  - Segunda aprobación de la misma medida devuelve 409 y no envía nada. (Review Focus 2)
  - Orden `fallida` con el mismo juez de turno: se reenvía con intento 2 y otro `orden_id`.
  - Orden `fallida` después del cambio de turno: no se reenvía; aparece medida `ratificacion`; al aprobarla el juez entrante salen las órdenes con su firma.
  - Juez deja de estar de turno entre la aprobación y el envío: no sale la orden y se crea la ratificación. (Review Focus 4)
  - `enviarOrden` lanza un error de red y luego responde 409: la orden queda como recibida, sin duplicar. (Review Focus 5)
  - `sim.estado()` lanza: `tick()` no lanza, el motor queda `conectado: false` y al siguiente tick correcto retoma sin repetir detecciones. (Review Focus 1)
  - Detección sin `captura` y con IP sin DNS pasivo: medida con recomendación `dominio`. (Review Focus 3)
  - Cambio de juez de turno con medidas pendientes deja una entrada `traspaso_turno` en la auditoría con sus ids.
  - Con el partido terminado no se crean medidas ni se envían órdenes.
- [ ] **Step 2–4:** Fallar, implementar, pasar.
- [ ] **Step 5:** Commit `feat: motor, decisiones y despacho`.
